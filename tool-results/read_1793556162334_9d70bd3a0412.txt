    60→    91→    91→# 3. MUST set bookmark attributes on every heading
    61→    92→    92→def add_heading(text, style, level=0):
    62→    93→    93→    key = f'h_{hashlib.md5(text.encode()).hexdigest()[:8]}'
    63→    94→    94→    p = Paragraph(f'<a name="{key}"/>{text}', style)
    64→    95→    95→    p.bookmark_name = key
    65→    96→    96→    p.bookmark_level = level
    66→    97→    97→    p.bookmark_text = text
    67→    98→    98→    p.bookmark_key = key
    68→    99→    99→    return p
    69→   100→   100→
    70→   101→   101→# 4. MUST use multiBuild (NOT build)
    71→   102→   102→doc = TocDocTemplate(output_path, pagesize=A4, ...)
    72→   103→   103→doc.multiBuild(story)
    73→   104→   104→```

   185→   216→   216→## Step 3: EDIT - Content Transformation
   186→   217→   217→
   187→   218→   218→**Before writing any code, restructure raw text into visual roles.** This is the most impactful quality step - skipping it produces "Word document with a PDF extension".
   188→   219→   219→
   189→   220→   220→### 3a. Typographic Role Extraction
   190→   221→   221→
   191→   222→   222→Parse raw text and categorize content into visual roles:
   192→   223→   223→
   193→   224→   224→| Role | ReportLab Mapping | Description |
   194→   225→   225→|------|------------------|-------------|
   195→   226→   226→| **Hero / Display** | Cover title (36-42pt) or section opener | 1-5 words, the emotional hook |
   196→   227→   227→| **Kicker / Eyebrow** | Subtitle or section intro (10-12pt, muted) | Tiny context line above main heading |
   197→   228→   228→| **Data Sculpture** | CalloutBox or bold stat block | Extract impactful numbers (97%, $4.2M, -45ms) |
   198→   229→   229→| **Pull Quote** | BlockQuote (italic + left indent 24pt + accent border) | Most provocative sentence, standalone |
   199→   230→   230→| **Body** | Standard paragraph | Everything else |
   200→   231→   231→
   201→   232→   232→**Rule**: Before writing any body paragraph, scan for numbers with units. Every metric like "revenue grew by 12%" or "latency dropped to 45ms" MUST be extracted into a CalloutBox or metrics table - never buried in paragraph prose. See §Data-to-Ink Ratio Rules below.
   202→   233→   233→
   203→   234→   234→### 3b. Section Pacing
   204→   235→   235→
   205→   236→   236→- If any H1 section has **>400 words** of continuous body text without visual breaks, split into H2 subsections or insert a visual break (table, chart, callout)
   206→   237→   237→- Aim for at least 1 visual element (table/chart/callout) per 2-3 pages of body text
   207→   238→   238→- Dense text walls are the #1 sign of poor report design
   208→   239→   239→
   209→   240→   240→### 3c. Content Sanitization for External Sources (MANDATORY when source is PDF/OCR/web)
   210→   241→   241→
   211→   242→   242→When content is extracted from an external PDF, OCR output, or web scrape, it may contain invisible garbage characters that cause garbled rendering. **You MUST sanitize the text content before writing it into any `Paragraph()` or `canvas.drawString()`.**
   212→   243→   243→
   213→   244→   244→This is different from `code.sanitize` (which cleans Python source code). Content sanitization cleans the **text data itself**.
   214→   245→   245→
   215→   246→   246→```python
   216→   247→   247→import re
   217→   248→   248→
   218→   249→   249→def content_sanitize(text: str) -> str:
   219→   250→   250→    """Strip invisible/control chars from externally-sourced text."""
   220→   251→   251→    # Remove control chars (except \n \t)
   221→   252→   252→    text = re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]', '', text)
   222→   253→   253→    # Remove zero-width chars
   223→   254→   254→    text = re.sub(r'[\u200b-\u200f\u2028-\u202f\u2060\ufeff]', '', text)
   224→   255→   255→    # Remove replacement char (upstream encoding error)
   225→   256→   256→    text = text.replace('\ufffd', '')
   226→   257→   257→    # Remove variation selectors
   227→   258→   258→    text = re.sub(r'[\ufe00-\ufe0f]', '', text)
   228→   259→   259→    # Remove private use area chars
   229→   260→   260→    text = re.sub(r'[\ue000-\uf8ff]', '', text)
   230→   261→   261→    return text
   231→   262→   262→```
   232→   263→   263→
   233→   264→   264→**When to use:**
   234→   265→   265→| Source | Must sanitize? |
   235→   266→   266→|--------|---------------|
   236→   267→   267→| User typed text in prompt | No (usually clean) |
   237→   268→   268→| Extracted from PDF via `pdf.py extract.text` | **YES** |
   238→   269→   269→| OCR output | **YES** |
   239→   270→   270→| Web scrape / HTML strip | **YES** |
   240→   271→   271→| LLM-generated content | No (usually clean) |
   241→   272→   272→
   242→   273→   273→⚠️ **Do NOT confuse** `code.sanitize` (Step 6, cleans Python code) with `content_sanitize()` (Step 3, cleans text data). They solve different problems.

   270→   301→   301→
   271→   302→   302→## Character Safety Rule (MANDATORY)
   272→   303→   303→
   273→   304→   304→Three rules for safe character handling in ReportLab PDFs:
   274→   305→   305→
   275→   306→   306→**a) Superscripts and subscripts**: Use `<super>`/`<sub>` tags, never raw Unicode superscript/subscript characters (e.g., `\u00b2`, `\u2082`).
   276→   307→   307→
   277→   308→   308→**b) Emoji**: ReportLab cannot render emoji. If content contains emoji, use Creative brief (HTML + Playwright).
   278→   309→   309→
   279→   310→   310→**c) Font fallback for mixed CJK/Latin text (MANDATORY)**: After registering fonts, you **MUST** call `install_font_fallback()` once. This automatically wraps missing-glyph characters in `<font>` tags inside every `Paragraph()`. No manual `<font name="...">` wrapping needed for mixed Chinese-English text. **Skipping this call is the #1 cause of Helvetica garbled text in CJK documents.**
   280→   311→   311→
   281→   312→   312→**d) canvas.drawString / drawRightString CJK font rule (MANDATORY)**: `install_font_fallback()` only works on `Paragraph()` objects. It does NOT affect `canvas.drawString()` / `canvas.drawRightString()` / `canvas.drawCentredString()`. If the text passed to any `canvas.draw*String()` call contains CJK characters (Chinese/Japanese/Korean), you **MUST** call `canvas.setFont('NotoSerifSC', size)` (or another registered CJK font) before drawing. Using FreeSerif / Helvetica / Times for CJK canvas text = garbled output.
   282→   313→   313→
   283→   314→   314→```python
   284→   315→   315→# ❌ WRONG — FreeSerif has no CJK glyphs, '科大讯飞' will be garbled
   285→   316→   316→canvas.setFont('FreeSerif-Italic', 8)
   286→   317→   317→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   287→   318→   318→
   288→   319→   319→# ✅ CORRECT — use CJK font for mixed text
   289→   320→   320→canvas.setFont('NotoSerifSC', 8)
   290→   321→   321→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   291→   322→   322→
   292→   323→   323→# ✅ ALSO CORRECT — pure English text can use FreeSerif
   293→   324→   324→canvas.setFont('FreeSerif-Italic', 8)
   294→   325→   325→canvas.drawString(x, y, 'Prepared by Strategy Advisory Team')
   295→   326→   326→```
   296→   327→   327→
   297→   328→   328→Mathematical/relational operators (×, ÷, ±, ≤, √, ∑, ≅, ∫, π, ∠, Δ, etc.) are safe to use as literal characters in `Paragraph()` - both Noto Sans SC and FreeSerif have these glyphs.
   298→   329→   329→
   299→   330→   330→| Need | Correct Method | Correct Example |
   300→   331→   331→|------|---------------|---------|
   301→   332→   332→| Superscript | `<super>` tag in `Paragraph()` | `Paragraph('10<super>2</super> × 10<super>3</super> = 10<super>5</super>', style)` |
   302→   333→   333→| Subscript | `<sub>` tag in `Paragraph()` | `Paragraph('H<sub>2</sub>O', style)` |
   303→   334→   334→| Bold | `<b>` tag in `Paragraph()` | `Paragraph('<b>Title</b>', style)` |
   304→   335→   335→| Math operators | Literal char in `Paragraph()` | `Paragraph('AB ⊥ AC, ∠A = 90°, and ΔABC ≅ ΔDCF', style)` |
   305→   336→   336→| Scientific notation | Combined tags in `Paragraph()` | `Paragraph('1.2 × 10<super>8</super> kg/m<super>3</super>', style)` |
   306→   337→   337→
   307→   338→   338→```python
   308→   339→   339→from reportlab.platypus import Paragraph
   309→   340→   340→from reportlab.lib.styles import ParagraphStyle
   310→   341→   341→from reportlab.lib.enums import TA_LEFT, TA_CENTER, TA_JUSTIFY
   311→   342→   342→
   312→   343→   343→body_style = ParagraphStyle(
   313→   344→   344→    name="ENBodyStyle",
   314→   345→   345→    fontName="FreeSerif",
   315→   346→   346→    fontSize=10.5,
   316→   347→   347→    leading=18,
   317→   348→   348→    alignment=TA_JUSTIFY,
   318→   349→   349→)
   319→   350→   350→
   320→   351→   351→# CJK Body (Chinese documents)
   321→   352→   352→cn_body_style = ParagraphStyle(
   322→   353→   353→    name="CNBodyStyle",
   323→   354→   354→    fontName="NotoSerifSC", fontSize=10.5, leading=18,
   324→   355→   355→    alignment=TA_LEFT,      # ← NEVER TA_JUSTIFY for CJK
   325→   356→   356→    wordWrap='CJK',         # ← MANDATORY for CJK
   326→   357→   357→    firstLineIndent=2*4.5*mm,
   327→   358→   358→)
   328→   359→   359→
   329→   360→   360→# Superscript: area unit
   330→   361→   361→Paragraph('Total area: 500 m<super>2</super>', body_style)
   331→   362→   362→
   332→   363→   363→# Subscript: chemical formula
   333→   364→   364→Paragraph('The reaction produces CO<sub>2</sub> and H<sub>2</sub>O', body_style)
   334→   365→   365→
   335→   366→   366→# Scientific notation
   336→   367→   367→Paragraph('Speed of light: 3.0 × 10<super>8</super> m/s', body_style)
   337→   368→   368→
   338→   369→   369→# Combined
   339→   370→   370→Paragraph('E<sub>k</sub> = mv<super>2</super>/2', body_style)
   340→   371→   371→
   341→   372→   372→# Bold heading
   342→   373→   373→Paragraph('<b>Chapter 1: Introduction</b>', header_style)
   343→   374→   374→
   344→   375→   375→# Math symbols
   345→   376→   376→Paragraph('When ∠ A = 90°, AB ⊥ AC and ΔABC ≅ ΔDEF', body_style)
   346→   377→   377→```
   347→   378→   378→
   348→   379→   379→**Pre-generation check - before writing ANY string, ask:**
   349→   380→   380→> "Does this string contain a character outside basic CJK or Mathematical/relational operators?"
   350→   381→   381→> If YES → it MUST be inside a `Paragraph()` with the appropriate tag.
   351→   382→   382→> If it is a superscript/subscript digit in raw unicode escape form → REPLACE with `<super>`/`<sub>` tag.
   352→   383→   383→
   353→   384→   384→**NEVER rely on post-generation scanning. Prevent at the point of writing.**
   354→   385→   385→
   355→   386→   386→**Encoding safety - before writing ANY content text:**
   356→   387→   387→> "Does this string contain Japanese kana (の, が, は etc.) or rare Unicode symbols?"
   357→   388→   388→> If YES → REPLACE with safe plain Chinese equivalents. Japanese kana (Hiragana U+3040-U+309F, Katakana U+30A0-U+30FF) frequently corrupt to U+FFFD (�) when code passes through LLM output, heredoc, or terminal encoding layers.
   358→   389→   389→> Common safe replacements: `活の真鲷`→`活缔真鲷`, `盐烤の鲭鱼`→`盐烤鲭鱼`, `烤の鸡串`→`炭烤鸡串`.
   359→   390→   390→> If the character is genuinely needed, verify it survives a full write→read round-trip with `open(file, encoding='utf-8')`.

The fallback chain is: English fonts → NotoSerifSC (primary) or Noto Sans SC (legacy), Chinese fonts → FreeSerif. For aesthetic optimization, Cyrillic text in NotoSerifSC/Noto Sans SC is automatically routed to FreeSerif (serif looks better for Cyrillic).

   485→   516→   516→### Page Breaks
   486→   517→   517→
   487→   518→   518→Follow the document type strategy defined in SOUL.md Rule 1.
   488→   519→   519→
   489→   520→   520→**Structural breaks (always - MANDATORY):**
   490→   521→   521→- Between cover page and TOC - **cover must NEVER share a page with anything else**
   491→   522→   522→- Between TOC and main content
   492→   523→   523→- Between main content and back cover
   493→   524→   524→
   494→   525→   525→**Content breaks (by document type):**
   495→   526→   526→- **Default (all document types)**: ❗ **Absolutely NEVER force page breaks before H1/H2** — content flows naturally, do not insert `PageBreak()` before section headings. This is an iron rule.
   496→   527→   527→- Resume / contract / letter → No content page breaks
   497→   528→   528→- Short article → No content page breaks
   498→   529→   529→- **Exception 1**: Academic papers / textbooks / teaching plans → `PageBreak()` before each H1 is acceptable (only if user explicitly requests academic formatting)
   499→   530→   530→- **Exception 2**: User explicitly requests page breaks between chapters
   500→   531→   531→
   501→   532→   532→**Anti-tear (mandatory — but with height limit):**
   502→   533→   533→```python
   503→   534→   534→from reportlab.platypus import KeepTogether
   504→   535→   535→from reportlab.lib.pagesizes import A4
   505→   536→   536→from reportlab.lib.units import inch
   506→   537→   537→
   507→   538→   538→# Maximum height for KeepTogether blocks: 40% of page height
   508→   539→   539→# Blocks taller than this should NOT be kept together — they cause
   509→   540→   540→# the preceding page to be mostly empty when the block gets pushed down.
   510→   541→   541→MAX_KEEP_HEIGHT = A4[1] * 0.4  # ~336pt ≈ 12cm
   511→   542→   542→
   512→   543→   543→def safe_keep_together(elements):
   513→   544→   544→    """Wrap elements in KeepTogether only if their total height is reasonable.
   514→   545→   545→    If too tall, keep only the FIRST TWO elements together (e.g. title + table/image header)
   515→   546→   546→    to prevent title-content separation, while letting the rest paginate naturally.
   516→   547→   547→    """
   517→   548→   548→    total_h = 0
   518→   549→   549→    for el in elements:
   519→   550→   550→        w, h = el.wrap(A4[0] - 2*inch, A4[1])
   520→   551→   551→        total_h += h
   521→   552→   552→    if total_h <= MAX_KEEP_HEIGHT:
   522→   553→   553→        return [KeepTogether(elements)]
   523→   554→   554→    elif len(elements) >= 2:
   524→   555→   555→        # Keep at least title + first element together to prevent title orphaning
   525→   556→   556→        return [KeepTogether(elements[:2])] + list(elements[2:])
   526→   557→   557→    else:
   527→   558→   558→        return list(elements)
   528→   559→   559→
   529→   560→   560→# Heading stays with first paragraph
   530→   561→   561→story.extend(safe_keep_together([
   531→   562→   562→    heading_paragraph,
   532→   563→   563→    first_body_paragraph,
   533→   564→   564→]))
   534→   565→   565→
   535→   566→   566→# Image + caption: keep together ONLY if image is small
   536→   567→   567→story.extend(safe_keep_together([image, caption_paragraph]))
   537→   568→   568→
   538→   569→   569→# Table title + table: keep together ONLY if table is short
   539→   570→   570→if len(table_data) <= 15:
   540→   571→   571→    story.extend(safe_keep_together([table_title, table]))
   541→   572→   572→else:
   542→   573→   573→    # Long table: just keep title with the table start
   543→   574→   574→    story.extend(safe_keep_together([table_title]))
   544→   575→   575→    story.append(table)
   545→   576→   576→```
   546→   577→   577→
   547→   578→   578→**⚠️ KEY INSIGHT:** `KeepTogether` is the #1 cause of “empty page with chart on next page”.
   548→   579→   579→When a `KeepTogether` block is taller than the remaining space on the current page,
   549→   580→   580→ReportLab pushes the **entire block** to the next page, leaving the current page mostly empty.
   550→   581→   581→**Always use `safe_keep_together()` to cap the maximum block height.**
   551→   582→   582→
   552→   583→   583→**⚠️ Note:** Do NOT use `KeepWithNext` - it is unreliable in ReportLab 4.x.

   554→   585→   585→### Vertical Spacing Standards
   555→   586→   586→* Before tables: `Spacer(1, 18)` after preceding text
   556→   587→   587→* After tables: `Spacer(1, 6)` before table caption
   557→   588→   588→* After table captions: `Spacer(1, 18)` before next content
   558→   589→   589→* Between paragraphs: `Spacer(1, 12)` (~1 line)
   559→   590→   590→* Between H3 subsections: `Spacer(1, 12)`
   560→   591→   591→* Between H2 sections: `Spacer(1, 18)` (~1.5 lines)
   561→   592→   592→* Between H1 sections: `Spacer(1, 24)` (~2 lines)
   562→   593→   593→* NEVER use `Spacer(1, X)` where X > 24, except for H1 major breaks or cover page elements

   564→   595→   595→### Cover Page: HTML/Playwright Unified Cover System
   565→   596→   596→
   566→   597→   597→**⚠️ Report route covers are ALWAYS generated via HTML/Playwright**, using the same 5-template system defined in `typesetting/cover.md`. This ensures visual consistency across all routes (Report, Creative, Academic) and avoids the limitations of ReportLab for complex cover layouts.
   567→   598→   598→
   568→   599→   599→**Pipeline (Report route):**
   569→   600→   600→1. Generate **body PDF** via ReportLab (start with TOC or content - **no cover in story[]**)  
   570→   601→   601→2. Generate **cover HTML** following `typesetting/cover.md` 5-template system  
   571→   602→   602→3. **Run `poster_validate.py check-html` on cover HTML** — fix any ERRORs before rendering (overflow:hidden, font fallback, etc.)  
   572→   603→   603→4. **Run `cover_validate.js` on cover HTML** — detects text-vs-decorative-line overlaps. Non-zero exit = must fix before proceeding.
   573→   604→   604→   ```bash
   574→   605→   605→   node "$PDF_SKILL_DIR/scripts/cover_validate.js" cover.html
   575→   606→   606→   ```
   576→   607→   607→5. Render cover HTML → single-page PDF via Playwright (`html2poster.js`) — **NOT `html2pdf-next.js`** (which converts absolute→static and destroys cover layout). **⚠️ MUST pass `--width 794px` for A4 documents** (A4 = 210mm = 794px @96dpi). Without this, `html2poster.js` defaults to 720px (=540pt), which is narrower than A4 (595pt) and causes page size mismatch after merging with the body PDF.  
   577→   608→   608→6. **Merge: insert cover as page 0** of body PDF using pypdf → output single final PDF
   578→   609→   609→
   579→   610→   610→> **Why not ReportLab covers?** ReportLab is excellent for structured content (tables, paragraphs, flowables) but painful for visual design (geometric accents, precise absolute positioning, web fonts). HTML/CSS handles these natively. One cover system, one visual standard, zero inconsistency.
